# 同音噪声与 ASR 纠错口径

转录是语音识别产物，数字、品牌、人名最容易被听错。处理原则只有一条：**照原样记，不替原文改答案。**

## 三类噪声

| 类型 | 例子 | 处理 |
|---|---|---|
| 数字同音 | 「武汉51144」疑为五万；「4万9千八」与「49800」并存 | 按原文写法进 `oral_quotes`；把疑似真值写进 `conflicts` 或 `unknowns` 并标「疑为同音」 |
| 品牌同音 | 宝俪 / 宝丽；昂缇娜 / 昂提娜 | 保留原始称呼，不做归一；需要归一的项目进 `conflicts` |
| 人名/称谓 | 杨院 / 谢院 / 孟院 在同一场里并存 | 不猜谁是谁；把三种说法并列进 `conflicts`，并把「最终主刀是谁」写进 `unknowns` |

## 三条硬规则

1. **不折算**：不得把你判断的正确值直接写进正文。原文说「三十万」就记三十万，即使你确信是三万；把「疑为三万」写进 `unknowns` 的 `why`。
2. **不静默择优**：两个数字并存时，不许挑一个看起来合理的写成事实。并列进 `conflicts`，至少两个版本。
3. **不据此下结论**：疑似噪声的数字不能作为判断依据（比如不能用它算差额、算月供、算折扣率）。要算，先说明这是按哪个口径算的。

## 为什么这么严

一次真实运行里，客户说的是「四万九千八，差一点点」，这句话被读成「已付四万九千八」，于是应付五万变成了三个支付金额并存的对账问题。金额一旦被错了归属，后面所有的折扣、分期、月供推算都跟着错——而这些错**不会**被机械校验拦住，因为每个数字都能在原文里找到。

## 报告里的写法

- `analysis_meta.limitations` 写一句：「金额与品牌存在 ASR 同音噪声（如 51144/五万、宝俪/宝丽），相关条目已在 conflicts 并列，未做折算。」
- `unknowns` 里逐条写：「该项原文为 X，疑为 Y，需与客户或录音复核后确定。」
